Workbench — Helpful Tips

The Workbench is your group’s project portal on the FishView server. You drop in three files — your R script, your tree, and a ZIP of images — and the server assembles a dated snapshot you can run with one click. Michael can re-run your code from the same page to help you debug.

This page collects the helpful tips that make the Workbench Just Work. The primary flow is the 3-drop uploader; a single-ZIP fallback exists if you prefer it.

Note

The Workbench lives at http://164.67.78.200:5052/workbench/ (same server as FishView — UCLA WiFi or Bruin Secure VPN). You log in with the same group code you use for FishView.

The 3-drop uploader (recommended)

On the Workbench dashboard you’ll see four drop zones:

Slot What goes here Required? Filename rule
1. run.R Your analysis script yes must end in .R
2. Tree file Your phylogeny yes must end in .tre, .tree, .nex, or .nwk
3. Images ZIP A ZIP of species images yes must end in .zip
4. Notes A notes.md file or free-text box optional .md / .txt

When you click Upload, the server builds a snapshot for you with the exact layout run.R expects:

snapshots/<timestamp>/
├── run.R                    ← your script, top level
├── data/
│   ├── <your-tree-file>     ← whatever name you uploaded
│   └── images/              ← contents of your images ZIP, extracted here
├── outputs/                 ← empty; your script writes here
└── notes.md                 ← only if you provided notes

You never have to think about the ZIP layout again — the server enforces it.

What run.R should expect to find

Because the server assembles the layout for you, your script can hard-code these relative paths:

library(ape)

# Tree — whatever filename you dropped in slot 2
tree <- read.tree("data/your-tree-file.tre")

# Images — extracted from the ZIP you dropped in slot 3
img_dir <- "data/images"
files <- list.files(img_dir, pattern = "\\.(png|jpg|jpeg)$", full.names = TRUE)

# Write outputs here
write.csv(results, "outputs/signal-test-results.csv")
ggsave("outputs/tree-with-color.pdf", plot = p, width = 10, height = 8)

Rules run.R must follow

  1. Read inputs from ./data/ using relative paths only.
  2. Write outputs to ./outputs/ — that’s the directory the run page serves from.
  3. Do not call setwd() — the Workbench runs your script with the snapshot directory as the working directory.
  4. Do not use install.packages() — the server has the course package set pre-installed (see Pre-installed packages below).
  5. No network calls unless you genuinely need them (e.g. rfishbase::species()). The 5-minute timeout will kill long-running scrapes.

Single-ZIP fallback (advanced)

Under “Advanced: upload one ZIP instead” on the dashboard, you can submit a single ZIP with this layout:

my-analysis.zip
├── run.R              ← REQUIRED entrypoint at top level
├── data/              ← REQUIRED directory
├── outputs/           ← REQUIRED directory (may be empty)
└── notes.md           ← OPTIONAL

The validator rejects this ZIP if run.R, data/, or outputs/ is missing from the top level, if paths contain .., or if the total exceeds 200 MB uncompressed.

If you’re using this path: on macOS Finder, select the contents of your folder (not the folder itself), then “Compress” — otherwise everything ends up wrapped one level deep.

Rules run.R must follow

  1. Read inputs from ./data/ using relative paths only:

    library(ape)
tree <- read.nexus("data/cirrhilabrini-pruned-tree.tre")
metrics <- read.csv("data/pavo-metrics.csv")

  2. Write outputs to ./outputs/:

    write.csv(results, "outputs/signal-test-results.csv")
ggsave("outputs/tree-with-color.pdf", plot = p, width = 10, height = 8)

  3. Do not call setwd() — the Workbench runs your script with the snapshot directory as the working directory, so relative paths Just Work.

  4. Do not use install.packages() — the server has the course package set pre-installed (see Pre-installed packages below). If you need a package that isn’t there, ping Michael.

  5. No network calls unless you genuinely need them (e.g. rfishbase::species()). The 5-minute timeout will kill long-running scrapes.

Hello-world run.R you can copy

# run.R — minimal example you can swap into your own analysis
library(ape)

# Read input
tree <- read.tree("data/example-tree.tre")
cat("Loaded tree with", length(tree$tip.label), "tips\n")

# Do something
pd <- sum(tree$edge.length)
cat("Total branch length:", round(pd, 2), "\n")

# Write output
write.csv(
  data.frame(metric = "total_branch_length", value = pd),
  "outputs/summary.csv",
  row.names = FALSE
)
cat("Wrote outputs/summary.csv\n")

Test it with the 3-drop uploader: drop run.R in slot 1, a tiny example-tree.tre (e.g. (a,b,c,d);) in slot 2, and any small ZIP of placeholder images in slot 3. Snapshot, run, done.

What happens after you upload

  1. Validation — server inspects the ZIP and rejects with a clear message if the shape is wrong.
  2. Snapshot — accepted ZIPs are extracted to snapshots/<timestamp>/ on the server. Your previous snapshots stay; nothing is overwritten.
  3. Dashboard view — your snapshot shows up on your group’s Workbench page with previews for images, PDFs, CSVs, and code.
  4. Run — you (or Michael) hit ▶ Run on a snapshot. The server executes Rscript --vanilla run.R in that snapshot’s directory and streams stdout/stderr to your browser in real time.
  5. Outputs — anything new written under outputs/ during the run becomes downloadable from the run’s summary page. Old snapshots and runs remain accessible — nothing is deleted automatically.

A run is independent of the snapshot it was launched from. The snapshot itself is immutable once uploaded; runs read from it and write to a separate runs/<run_id>/ directory.

Limits

Limit Value Why
Max ZIP size 200 MB uncompressed Mac mini disk
Run timeout 5 minutes wall time Avoid runaway processes
Concurrent runs per group 1 Avoids races on outputs/
Snapshot history unlimited We’ll prune manually if needed

Tips for a smooth workflow

  • Iterate small. Drop in a minimal run.R that just loads your data and prints dim() first. Once that works, add one analysis step at a time.
  • Name your files clearly. cirrhilabrini-pgls-attempt-3.R is more useful in the snapshot list than analysis.R.
  • Use the notes box. A one-paragraph “what I’m trying / what I’m stuck on” helps Michael troubleshoot when he visits your snapshot.
  • Read the run log. When ▶ Run fails, the SSE log shows the exact R error message. Fix in your local R, re-upload, re-run.
  • Don’t re-upload to “fix” — re-upload to make a new attempt. Snapshots are versioned; treat each one as a checkpoint of your progress.

Troubleshooting

Problem Likely cause Fix
Upload rejected: “run.R not found at top level” You used the single-ZIP fallback and wrapped everything in a folder Either use the 3-drop uploader instead, or on macOS Finder select the contents of your folder (not the folder) then “Compress”
Run finishes immediately with exit code 1 R syntax error in run.R Read the stderr stream — line number is in the message
cannot open file 'data/...' Wrong relative path, or file not in data/ Check the snapshot view — your ZIP’s contents are listed there
Run hangs and gets killed at 5 min Long-running rfishbase call or slow MCMC Cache the result locally and put the cached file in data/ instead
“Concurrent run already in progress” Two groupmates hit Run at the same time Wait for the first run to finish (visible on the dashboard)
