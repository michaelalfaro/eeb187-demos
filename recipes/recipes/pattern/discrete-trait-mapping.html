Recipe 15: Discrete Trait Mapping

Does a pattern type (bars, spots, stripes) have a structured evolutionary history?

The Big Question

Does the presence of bars, spots, or stripes map onto the phylogeny in a structured way — or did the same pattern evolve independently many times?

This Is an Instance Of…

Ancestral State Reconstruction / Character Evolution

You are treating a pattern type (bars present / absent, spots present / absent) as a discrete character and asking whether it evolved once and was retained, or evolved repeatedly. The core method is ancestral state reconstruction (ASR) — estimating the most probable state at each internal node of the phylogeny given the observed tip states.

This is the same logic that evolutionary biologists use to infer when flight was lost in birds, when viviparity evolved in lizards, or when C4 photosynthesis arose in grasses. Here, your character is a visible color pattern element that you score yourself from images.

Why This Matters for Your Clade

Discrete trait mapping answers a question that pavo metrics alone cannot: did a recognizable pattern type arise once and diversify, or is it a convergent solution appearing over and over?

Natural fits for this recipe
  • Balistoidea — Triggerfishes span plain, spotted, striped, and boldly barred forms. Did bold bars arise once in the triggerfishes or multiple times across the group?
  • Pomacanthidae — Many angelfishes shift dramatically from juvenile to adult pattern. Score adults only, and ask whether bold vertical banding is ancestral or repeatedly derived.
  • Scarinae — Terminal-phase males often carry bold stripes and spots. Did these elements track phylogeny or reflect repeated convergence?
  • Acanthuridae — The contrast between the plain-bodied Naso unicornfishes and the patterned surgeonfish core is stark. When did plain coloration evolve in the group?
  • Any clade — Pick whichever binary trait (bars, spots, eyespots, ocelli, etc.) varies across your species and has a clear visual definition you can apply consistently from images.

The pattern of gains and losses tells you about selective pressure. A single origin that persists (low rate of change) suggests strong stabilizing selection or functional constraint. Many independent gains suggest that the same selection pressure recurs in different lineages.

The Method

Step 1 — Define your trait precisely. Before touching any code, write a one-sentence definition of what you are scoring. For bars: “a bar is a vertical dark stripe at least as wide as one eye diameter that crosses more than half the body depth.” This level of precision lets a second person score the same images and get the same answer.

Step 2 — Score your images. Go through each species in your image set (the same images you used for pavo). Record a 1 if the trait is present, 0 if absent, and NA if the image quality is too low to judge. Put the result in a two-column CSV: species, has_bars (or whatever you named the trait).

Step 3 — Match to the tree. Keep only the species that appear in both your CSV and your mini-tree. Drop tips for which you have no score.

Step 4 — Plot trait on tips. Color tree tips by trait state (two colors from the course palette). This visual inspection alone is informative — if one color is clustered in one part of the tree, structure exists.

Step 5 — Run ancestral state reconstruction. Use ace() from the ape package with type = "discrete" and model = "ER" (equal-rates: a single rate parameter governs gains and losses). This is the most conservative assumption. The function returns, for each internal node, the estimated probability of being in each state.

Step 6 — Plot pie charts on nodes. Each internal node gets a pie chart showing P(absent) and P(bars). Nodes with mixed probabilities (roughly 50/50) are genuinely uncertain — that is honest. Nodes with one color dominant are informative.

Step 7 — Count transitions. Use phytools::make.simmap() (optional, see code below) to stochastically map transitions. Summarizing 100 maps gives you a distribution over the number of gains and losses, which is more honest than a single reconstruction.

How to Interpret Results

What you see What it means
Trait tips cluster in one clade Single origin (or a single origin plus a few losses). The pattern is phylogenetically structured.
Trait tips scattered across the whole tree Many independent gains, many losses, or both. Low phylogenetic signal in this binary trait.
Root node pie is mostly one color The ancestral state is probably resolved. The other state is derived.
Root node pie is 50/50 The ancestral state cannot be resolved with your data — both scenarios are equally supported.
High rate parameter (printed by ace) Trait is labile; changes frequently relative to branch lengths.
Low rate parameter Trait is conserved; once present, it persists.

Pitfalls to avoid:

  • Inconsistent scoring is fatal. If “bars present” means different things for different species, your reconstruction will be garbage. Score all species in one sitting using your written definition.
  • NA vs. 0 matters. An unscored species is not the same as an absent trait. Drop NAs before running ace().
  • Equal-rates is a simplification. Gains and losses need not occur at the same rate. After you get the basic result, you can compare ER to ARD (all-rates-different) with AIC(). But ER is appropriate for an undergraduate project.
  • Tree uncertainty. You are using a point-estimate tree. The reconstruction could differ on an alternative topology. Mention this as a caveat.

The Code

library(ape)
library(phytools)

source("https://michaelalfaro.github.io/eeb187-demos/recipes/code/helpers.R")

# ── Load your tree ────────────────────────────────────────────────
bundle <- load_bundle("path/to/your/bundle")
tree   <- bundle$tree

# ── Load your scored trait CSV ────────────────────────────────────
# Create this file yourself from visual inspection of your images.
# Two columns: species (underscore format, e.g. Balistes_vetula), has_bars (0 or 1)
scored <- read.csv("my_bar_scores.csv", stringsAsFactors = FALSE)

# Remove rows with NA scores
scored <- scored[!is.na(scored$has_bars), ]

# Named vector: values are 0/1, names are species
bars <- setNames(scored$has_bars, scored$species)

# ── Prune tree to scored species ──────────────────────────────────
overlap     <- intersect(names(bars), tree$tip.label)
tree_pruned <- drop.tip(tree, setdiff(tree$tip.label, overlap))
bars        <- bars[tree_pruned$tip.label]

cat("Scored species in tree:", length(overlap), "\n")
cat("Trait prevalence: n =", sum(bars), "with trait,",
    sum(bars == 0), "without\n")

# ── Plot tips colored by trait state ──────────────────────────────
cols <- c("0" = "#2a9d8f", "1" = "#e76f51")

png("fig-trait-tips.png", width = 2400, height = 2000, res = 300)
plot(tree_pruned,
     type      = "fan",
     cex       = 0.45,
     edge.width = 2.5,
     tip.color = cols[as.character(bars)])
legend("topleft",
       legend = c("No bars", "Bars"),
       fill   = c("#2a9d8f", "#e76f51"),
       cex    = 1.2,
       bty    = "n")
title("Trait distribution: bars")
dev.off()

# ── Ancestral state reconstruction ────────────────────────────────
anc <- ace(as.factor(bars), tree_pruned, type = "discrete", model = "ER")

cat("\nTransition rate (equal-rates model):\n")
cat("  q =", round(anc$rates, 4), "\n")

cat("\nAncestral state at root:\n")
cat("  P(no bars) =", round(anc$lik.anc[1, 1], 3), "\n")
cat("  P(bars)    =", round(anc$lik.anc[1, 2], 3), "\n")

# ── Plot reconstruction with pie charts on nodes ──────────────────
png("fig-ancestral-state.png", width = 2400, height = 2000, res = 300)
plot(tree_pruned,
     type       = "fan",
     cex        = 0.40,
     edge.width = 2)
nodelabels(pie    = anc$lik.anc,
           piecol = c("#2a9d8f", "#e76f51"),
           cex    = 0.40)
legend("topleft",
       legend = c("No bars", "Bars"),
       fill   = c("#2a9d8f", "#e76f51"),
       cex    = 1.2,
       bty    = "n")
title("Ancestral state reconstruction: bars")
dev.off()

# ── Optional: Stochastic character mapping ────────────────────────
# This gives a distribution over the number of transitions rather
# than a single point estimate. Run 100 simulations and summarize.
set.seed(42)
maps   <- make.simmap(tree_pruned, as.factor(bars), model = "ER", nsim = 100,
                      message = FALSE)
map_summary <- describe.simmap(maps)

cat("\nStochastic mapping summary (100 simulations):\n")
cat("  Mean transitions (0 -> 1):", round(mean(map_summary$count[, "0,1"]), 1), "\n")
cat("  Mean transitions (1 -> 0):", round(mean(map_summary$count[, "1,0"]), 1), "\n")

# Plot the summary map
png("fig-simmap.png", width = 2400, height = 2000, res = 300)
plot(map_summary,
     type   = "fan",
     fsize  = 0.40,
     colors = c("0" = "#2a9d8f", "1" = "#e76f51"),
     lwd    = 2)
add.simmap.legend(colors = c("0" = "#2a9d8f", "1" = "#e76f51"),
                  x      = 0, y = 0,
                  prompt = FALSE,
                  fsize  = 1.0)
title("Stochastic character mapping: bars")
dev.off()

What to report on your poster:

  • The tip-colored tree (fast visual check for clustering)
  • The pie-chart reconstruction (your main result)
  • The root-state probabilities (P(absent) vs. P(bars))
  • The estimated number of transitions from the stochastic mapping
  • A one-sentence interpretation: “Bars appear to have evolved [once / twice / multiple times] in this family, with [high / low] probability that the ancestor was [barred / unbarred].”

From the Literature

Pagel, M. (1994). Detecting correlated evolution on phylogenies: a general method for the comparative analysis of discrete characters. Proceedings of the Royal Society B, 255, 37–45. The foundational paper for comparing discrete character evolution across phylogenies. Introduces the likelihood framework that underlies ace(). Read the methods section to understand why equal-rates versus all-rates-different models exist and what the log-likelihood ratio test measures.

Schluter, D., Price, T., Mooers, A. O., & Ludwig, D. (1997). Likelihood of ancestor states in adaptive radiation. Evolution, 51, 1699–1711. Establishes the connection between ancestral state reconstruction and inference about adaptive origins. Explains when ancestral state reconstruction is reliable (many taxa, short branches near the root) and when it is not (long branches, few taxa, fast-evolving trait).

Revell, L. J. (2012). phytools: an R package for phylogenetic comparative biology (and other things). Methods in Ecology and Evolution, 3, 217–223. Documents the make.simmap() function used in the stochastic mapping extension above. If you use the simmap output in your poster, cite this paper.
